# 账户数据删除与保留契约实施计划

## 状态

- 当前状态：进行中（契约定义与实施设计阶段）。
- 负责模块：Happy App、happy-server 与隐私文档维护者。
- 建立日期：2026-08-10。
- 外部依赖：需产品/隐私负责人确认账户级删除、导出和可适用保留期的对外契约。

## 背景与证据

当前 App 能删除单个 session 和已注册的 push token。服务端删除
session 后会尝试删除附件对象，但对象存储失败目前被记为非致命，没有持久重试或已完成实物删除的证据。仓库中也没有账户级删除或加密数据导出的已实现工作流。

所以，隐私政策只描述已实现的 session 删除和 push token 删除，不再声称
固定 30 天内全部永久删除。本计划记录需要补齐的产品和实现工作，不把未验证的能力写成当前事实。

## 目标

在有明确的保留契约后，提供可审计的账户级数据处理能力：可确认地删除或按约定保留
账户相关记录、服务端对象和必需的运营元数据，并与对外隐私说明一致。

## 实施步骤

1. 确认账户删除、导出、备份、安全日志和第三方提供商数据的保留规则，并为每一项记录所有者与截止时间。
2. 为 App 和 API 设计一个需要重新认证的账户级删除操作，明确 session、machine、credential、push token、
   service token、附件和 Sync v4 journal 的处理方式。
3. 将附件删除改为可重试、可观测的持久任务，不把对象存储失败静默地当作成功。
4. 实现 App 确认界面和导出能力（仅在第 1 步确认需要时），并修改隐私政策与 API 文档。

## 验收标准

- 有一份被接受的数据清单，涵盖每类记录、其保留理由、删除或导出路径与负责者。
- 账户级删除在授权、重试和失败情况下都有自动化测试，不会误删别的账户或无主记录。
- 附件清理失败可以重试并留下不含 payload 的运维证据；一次成功不代表未证实的批量或保留保证。
- 隐私政策、App 界面、API 和测试对已实现的删除/导出范围使用同一份契约。
- 需要的云端工作流和实际提供商验证有精确 run URL；不以本机模拟替代对象存储或第三方保留证据。
